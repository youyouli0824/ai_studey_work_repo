---

## 一、项目概述

### 1.1 项目背景

现有的 MySQL 数据库中维护着职工相关数据（`t_employees` 员工表、`t_departments` 部门表、`t_jobs` 职位表，含 107 条样例数据），数据只能通过命令行或直接操作数据库进行查看，缺少直观、易用的可视化管理系统。本系统旨在提供一个基于 Web 的职工信息管理平台，方便用户对职工数据进行浏览、查询、维护与统计。

### 1.2 项目目标

1. 提供清晰、友好的中文可视化界面，替代命令行式的数据查看。
2. 实现职工信息的**增删改查（CRUD）**与**多条件组合查询**。
3. 提供**分页浏览**与**分类统计**能力，降低大数据量下的使用难度。
4. 通过**仪表盘图表**直观呈现整体数据概况（人数、薪资、部门、职位、入职趋势）。

### 1.3 项目范围

- **范围内**：职工信息管理、组合查询、分页、批量删除、仪表盘统计、分类统计、中文界面。
- **范围外（本期不做）**：用户登录/权限控制、数据导出 Excel、审计日志、多角色管理、数据库在线编辑。

### 1.4 术语说明

| 术语 | 说明 |
|---|---|
| 员工（Employee） | `t_employees` 表中的一条记录，对应一名职工 |
| 部门（Department） | `t_departments` 表中的一条记录，员工可归属某部门 |
| 职位（Job） | `t_jobs` 表中的一条记录，员工担任的岗位 |
| 仪表盘 | 首页总览页面，展示统计卡片与图表 |
| CRUD | 增（Create）、查（Read）、改（Update）、删（Delete） |

## 四、后端接口需求

> 接口统一前缀：`/api/v1`；数据格式：JSON。

| 方法 | 路径 | 说明 | 用途 |
|---|---|---|---|
| GET | `/employees/search` | 组合条件查询 + 分页，返回 `{total, page, page_size, items}` | 员工管理列表/查询 |
| GET | `/employees` | 基础分页列表（skip / limit 参数） | 列表浏览、仪表盘取数 |
| GET | `/employees/{id}` | 按 ID 查询单个员工 | 详情 |
| POST | `/employees` | 新增员工（ID 由后端自动生成），返回 201 | 新增 |
| PUT | `/employees/{id}` | 更新员工（只更新传入字段） | 编辑 |
| DELETE | `/employees/{id}` | 删除员工，成功返回 204 | 删除 |
| GET | `/find/{name}` | 按名模糊查找员工 | 快捷查找 |
| GET | `/departments` | 部门列表 | 下拉字典 |
| GET | `/jobs` | 职位列表 | 下拉字典、薪资区间 |
| GET | `/overview` | 仪表盘总览统计（基础指标 + 部门统计 + 职位统计 + 入职年份分布） | 仪表盘/分类统计 |

### 4.1 接口通用约定

- **成功响应**：直接返回数据实体或数据列表。
- **统一错误响应**：`{ "code": <HTTP状态码>, "message": "<中文提示>" }`。
- **异常分类**：
  - 404 → 资源不存在（如「员工不存在」）；
  - 422 → 请求参数校验失败；
  - 500 → 服务器内部错误（兜底）。

## 五、数据需求

### 5.1 数据库环境

| 项 | 值 |
|---|---|
| 数据库类型 | MySQL |
| 数据库名 | `my-first-sql` |
| 编码 | `utf8mb4` |
| 连接方式 | PyMySQL + SQLAlchemy |

### 5.2 数据表

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `t_employees` | 员工表 | `EMPLOYEE_ID`（varchar 主键，无自增）、`FIRST_NAME`、`LAST_NAME`、`EMAIL`、`PHONE_NUMBER`、`HIRE_DATE`、`JOB_ID`、`SALARY`（varchar）、`COMMISSION_PCT`、`MANAGER_ID`、`DEPARTMENT_ID` |
| `t_departments` | 部门表 | `DEPARTMENT_ID`（主键）、`DEPARTMENT_NAME`、`MANAGER_ID`、`LOCATION_ID` |
| `t_jobs` | 职位表 | `JOB_ID`（主键）、`JOB_TITLE`、`MIN_SALARY`、`MAX_SALARY` |

> **重要约束（数据特征）**：`t_employees` 各列均为 `varchar`（含主键，无自增）。因此：
> 1. 新增员工时员工编号需由后端取「当前最大编号 + 1」生成；
> 2. 对薪资等数值列进行聚合（AVG / MAX / MIN）时，必须先转为数值类型，否则会按字符串比较出错。

1. **后端**（端口 8000）：
   ```bash
   cd MySQL_Project_backend
   python -m uvicorn main:app --reload --port 8000
   ```


## 九、风险与说明

| 风险/说明 | 影响 | 建议 |
|---|---|---|
| `t_employees` 列为 varchar，数值运算需强转 | 数值聚合可能出错 | 已在后端聚合处 `cast(..., Float)` 处理 |
| 主键无自增，ID 由程序生成 | 并发新增可能产生重复 ID | 当前单用户场景可接受；后续可引入事务锁或自增改造 |
| 批量删除采用逐个调用删除接口 | 数据量大时请求较多 | 可考虑新增批量删除接口 |
| 生产环境无代理 | 前端构建后 `/api` 无法直达后端 | 需配置反向代理或调整接口地址 |
| 无登录鉴权 | 数据无访问控制 | 若对外开放需补充鉴权 |
