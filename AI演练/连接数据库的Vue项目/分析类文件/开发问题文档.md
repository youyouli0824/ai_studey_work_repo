## 二、问题详情

### 2.1 数据库设计类问题

#### P01 主键无自增导致新增失败 【已解决 · 严重】

- **现象**：调用新增员工接口时插入失败，提示主键 `EMPLOYEE_ID` 无默认值。
- **原因**：`t_employees` 表结构设计为所有列均为 `varchar`，主键 `EMPLOYEE_ID` 同样为 `varchar` 类型且**没有自增 / 默认值**。直接插入不带主键的记录会触发数据库主键约束错误。
- **处理**：在 `main.py` 的 `create_employee` 中由后端自动生成编号——先查询当前最大编号（转为数值），`+ 1` 后作为新记录的主键再插入。
- **遗留风险**：并发新增时取最大值 + 1 可能重复；当前单用户场景可接受。

```python
# main.py create_employee 关键代码
max_id = db.query(
    func.max(cast(EmployeeModel.EMPLOYEE_ID, Float))
).scalar() or 0
next_id = int(max_id) + 1
```

#### P02 varchar 数值列聚合按字符串比较出错 【已解决 · 严重】

- **现象**：`MAX`、`MIN`、`AVG` 聚合结果异常（例如最大薪资算错）。
- **原因**：数据库中 `SALARY` 列是 `varchar` 类型，SQL 的 `MAX` / `MIN` 会按**字符串**排序比较（如 "9999" < "10000"），得到错误的最大/最小值；数值平均也无法正确计算。
- **处理**：聚合前使用 `cast(EmployeeModel.SALARY, Float)` 强转为数值，再执行 `func.avg / func.max / func.min`；部门平均薪资同样先强转后聚合。
- **注意点**：组合查询接口 `search_employees` 中的薪资区间过滤仍直接使用 `SALARY >= min_salary` 比较，依赖 MySQL 的隐式转换，数据量大或边界值场景下存在隐患，建议后续也显式强转。

### 2.2 后端开发类问题

#### P03 跨域（CORS）请求被拦截 【已解决 · 严重】

- **现象**：前端页面（5173 端口）请求后端（8000 端口）时，浏览器控制台报 CORS 错误。
- **原因**：前后端分离，前端与后端处于不同源（协议/域名/端口不同）。
- **处理**：后端注册 `CORSMiddleware`，允许来源、方法、请求头均为 `*`。
- **坑点**：当 `allow_origins` 为 `"*"` 时，`allow_credentials` 必须为 `False`，否则中间件会报错。
- **后续建议**：生产环境应收敛 `allow_origins` 为实际前端域名，避免全开。

#### P04 未捕获异常返回不友好 【已解决 · 中】

- **现象**：后端抛错时前端只能拿到服务端堆栈/默认错误页，难以定位与提示。
- **原因**：FastAPI 默认异常响应格式不适合直接面向用户。
- **处理**：注册三层全局异常处理器，统一响应结构 `{code, message}`：
  1. `HTTPException` → 返回对应状态码 + 中文 message（如「员工不存在」404）；
  2. `RequestValidationError` → 统一 422 +「请求参数校验失败」；
  3. `Exception` 兜底 → 统一 500 +「服务器内部错误」。

#### P05 参数校验 422 提示不友好 【已解决 · 中】

- **现象**：提交类型错误字段（如薪资传字符串）时，默认 422 返回英文 errors。
- **原因**：Pydantic 校验失败的默认响应为英文结构。
- **处理**：见 P04 的 `RequestValidationError` 处理器，统一包装为中文 message，并携带 `detail` 便于排查。
- **预防**：`schemas.py` 中对字段加了 `min_length / max_length / gt / ge` 约束，前端表单同步做了校验（必填、邮箱格式、薪资 > 0、提成 0~100）。

#### P06 新增时最大编号为空处理 【已解决 · 中】

- **现象**：表中无数据时 `MAX` 返回 `None`，`int(None)` 报错。
- **原因**：`func.max(...).scalar()` 在空表时返回 `None`。
- **处理**：`... or 0`，保证空表时编号从 1 开始。

### 2.3 前后端联调类问题

#### P07 部门/职位显示英文 ID 【已解决 · 高】

- **现象**：表格与下拉框中部门、职位显示为英文 ID（如 `80`、`SA_REP`），不符合中文界面需求。
- **原因**：数据库原始数据为 ID 形式；后端返回原始字段。
- **处理**：前端新增 `src/utils/labels.js` 中文映射字典：
  - `DEPARTMENTS_CN`：部门 ID → 中文名；
  - `JOBS_CN`：职位 ID → 中文名；
  - 提供 `departmentLabel / jobLabel` 函数，**映射缺失时回退英文**，保证信息不丢失。

#### P08 提成比例单位不一致 【已解决 · 中】

- **现象**：表单填写 25（表示 25%），保存后表格显示异常。
- **原因**：数据库中 `COMMISSION_PCT` 存储为小数（0.25），而界面按百分比（0~100）理解更符合习惯。
- **处理**：
  - 编辑回显时 `小数 × 100` 转为百分比；
  - 提交时 `百分比 ÷ 100` 转为小数后再传给后端。

#### P09 日期格式不一致 【已解决 · 中】

- **现象**：日期选择器值格式与后端 `date` 类型不匹配，导致 422 或查询无结果。
- **原因**：Element Plus `el-date-picker` 默认返回 Date 对象，Pydantic `date` 字段期望 `YYYY-MM-DD` 字符串。
- **处理**：日期选择器统一 `value-format="YYYY-MM-DD"`；日期范围查询拆为 `hire_date_start / hire_date_end` 传给后端做区间过滤。

### 2.4 前端开发类问题

#### P10 ECharts 图表不渲染 / 尺寸错位 【已解决 · 中】

- **现象**：图表首次渲染为空、或窗口缩放后图表溢出容器。
- **原因**：图表初始化时机早于容器布局完成；窗口尺寸变化后图表未自适应。
- **处理**：封装通用组件 `ChartBox.vue`：
  - `nextTick()` 后再 `echarts.init`；
  - `option` 变化时 `setOption(option, true)` 全量刷新；
  - 监听 `window.resize` 调用 `resize()`；
  - 组件销毁时 `dispose()` 释放实例，避免内存泄漏。

#### P11 删除当前页最后一条后分页停在空页 【已解决 · 低】

- **现象**：删除某页最后一条记录后，列表为空但页码仍在该页。
- **原因**：删除后未处理页码回退。
- **处理**：删除成功后若「当前页数据长度为 1 且页码 > 1」则页码减一，再重新加载列表；批量删除逻辑同理。

#### P12 空值显示不友好 【已解决 · 低】

- **现象**：无提成、无直属上级的记录显示空白或 `null`。
- **原因**：未对空值做统一展示。
- **处理**：`src/utils/format.js` 统一格式化：薪资千分位 + `¥`、提成转百分比、空值统一显示 `-`；`MANAGER_ID` 为空显示占位符 `—`。

### 2.5 环境与部署类问题

#### P13 批量删除逐条请求 【待优化 · 低】

- **现状**：批量删除使用 `Promise.all` 逐条调用单删接口。
- **问题**：数据量大时产生 N 个请求，存在性能与一致性问题（部分成功部分失败）。
- **建议**：后端新增 `POST /employees/batch-delete` 批量删除接口，前端一次请求完成。

#### P14 生产构建后 `/api` 无代理 【待处理 · 低】

- **现状**：开发模式下 `/api` 由 Vite 代理到 `http://127.0.0.1:8000`；`npm run build` 产物直接访问时 `/api` 无法到达后端。
- **问题**：生产部署必须配置反向代理（如 Nginx 将 `/api` 转发到 8000），或将 Axios `baseURL` 指向实际后端地址。

## 三、经验总结

### 3.1 数据库设计层面

1. **数值列应使用数值类型**。真实开发中薪资、金额等字段应定义为 `DECIMAL / DOUBLE / INT`，避免 `varchar` 带来的聚合与比较隐患。
2. **主键应自增或有明确生成策略**。无自增主键时，服务端需自行保证编号唯一，最好结合事务或数据库序列。
3. **编码统一使用 `utf8mb4`**，避免中文乱码。

### 3.2 后端层面

1. **全局统一异常处理**，让错误响应结构一致、提示中文友好，前端只需处理一种格式。
2. **参数校验双保险**：Pydantic 层 + 前端表单校验，缺一不可。
3. **数据库会话正确释放**：`get_db` 依赖中使用 `try/finally` 保证 `Session` 关闭。

### 3.3 前后端联调层面

1. **提前约定字段格式**：日期格式、百分比/小数、分页参数命名（`page` / `page_size`）应在一开始对齐。
2. **统一 Axios 封装**：解包 `response.data`、统一错误 message，减少重复代码。
3. **翻译字典集中管理**：中文映射单独放在 `utils/labels.js`，便于维护与扩展。

### 3.4 前端层面

1. **通用组件封装**：ECharts 封装为 `ChartBox.vue` 后，多页面复用且规避初始化/自适应坑。
2. **空值与格式化统一处理**：`format.js` 集中格式化，保证全站展示一致。
