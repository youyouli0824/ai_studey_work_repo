# 职员各部门工作交流系统 — 接口文档

> 版本：V3.0 · 2026-08-21 · 按**五大功能模块**重构组织，覆盖登录鉴权、个人中心、群聊、私聊、禁言、总裁管理、员工管理与统计全部 33 个接口。

---

## 一、通用说明

- **Base URL**：`http://127.0.0.1:8000/api/v1` · 数据格式 JSON · 编码 UTF-8
- **鉴权**：除 `POST /auth/login` 外均需请求头 `Authorization: Bearer <token>`（登录成功返回）
- **分页参数**：`page`（≥1，默认 1）、`page_size`（1~100，默认 10 或 20），消息/列表类分页统一返回 `{total, items}`
- **错误响应**：`{ "code": <HTTP码>, "message": "<中文提示>" }`

**错误码**：

| 状态码 | 含义 |
|---|---|
| 400 | 业务校验失败（如原密码错误、姓名重复、不能操作本人） |
| 401 | 未登录 / 登录已失效 |
| 403 | 无权限 / 被禁言 / 操作范围越权 |
| 404 | 资源不存在（员工、禁言记录、接收者） |
| 422 | 请求参数校验失败 |
| 500 | 服务器内部错误 |

**角色**：`STAFF` 普通职员 · `MANAGER` 管理部门职员 · `PRESIDENT` 总裁

**权限矩阵**：

| 角色 | 可访问模块 |
|---|---|
| STAFF | 认证与个人中心、群聊、私聊 |
| MANAGER | 以上全部 + 禁言管理 + 员工管理与统计 |
| PRESIDENT | 以上全部 + 总裁管理（任免管理层） |

| # | 模块 | 核心功能 | 接口数 | 权限 |
|---|---|---|---|---|
| 一 | **认证与个人中心** | 登录鉴权、退出、查看/修改个人信息、修改密码、上传头像 | 6 | 登录 |

## 三、模块一：认证与个人中心

### 3.1 模块功能

> 本模块是系统的**入口与身份基石**：负责登录鉴权（发放 Token）、退出登录、查询当前登录职员信息，以及个人资料的维护——修改邮箱/电话、修改密码、上传头像。登录账号同时支持「员工编号」和「职员姓名（英文不区分大小写）」两种方式，用户名即登录凭证，头像路径与个人联系方式集中在此模块维护。

### 3.2 接口一览

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 1 | POST | `/auth/login` | 登录（返回 token + 用户信息） |
| 2 | POST | `/auth/logout` | 退出登录 |
| 3 | GET | `/auth/me` | 获取当前登录职员信息 |
| 4 | PUT | `/me` | 修改个人信息（邮箱/电话） |
| 5 | PUT | `/me/password` | 修改密码 |
| 6 | POST | `/me/avatar` | 上传头像（multipart） |

### 3.3 接口详解

**1. POST `/auth/login`** — 登录
- body：`{username, password}`
  - `username` 为**职员姓名**（名+空格+姓，英文不区分大小写）或**员工编号**，两者任选其一
  - `password` 初始默认 `123456`
- 成功 `200`：`{token, user}`（`user` 见「四、数据对象 · 用户对象」）
- 失败 `401`「账号或密码错误」

**2. POST `/auth/logout`** — 退出登录
- 成功 `200`：`{message}`（Token 为无状态签名，前端清除本地凭证即可）

**3. GET `/auth/me`** — 获取当前登录职员信息
- 成功 `200`：用户对象（含 `EMPLOYEE_ID`、`name`、`role`、`avatar`、`DEPARTMENT_ID` 等）
- 作用：前端用于渲染侧边栏个人头像、角色标识与所属部门

**4. PUT `/me`** — 修改个人信息
- body（均可选，只更新传入字段）：`{EMAIL, PHONE_NUMBER}`
- 成功 `200`：更新后的用户对象
- 说明：姓名、角色、部门**不可自行修改**，只能修改联系方式

**5. PUT `/me/password`** — 修改密码
- body：`{old_password, new_password}`
- 成功 `200`：`{message}`「密码修改成功」；原密码错误 `400`「原密码错误」

**6. POST `/me/avatar`** — 上传头像
- form-data：`file`（图片文件）
- 限制：仅支持 JPG/PNG/GIF/WebP，大小 ≤ 5MB
- 成功 `200`：`{avatar: "/uploads/avatars/xxx.png"}`（可直接用于 `<img src>`）

## 四、模块二：群聊

### 4.1 模块功能

> 本模块提供**部门群 + 全员群**两级群聊能力：职员可查看自己加入的群聊列表（部门群按所属部门自动入群，全员群覆盖全体职员），获取群聊历史消息（分页、按时间升序），以及在群内发言。群发言受**禁言状态**约束——被禁言的职员无法在群聊中发言（`403`），且未分配部门的职员无法使用部门群功能。

### 4.2 接口一览

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 7 | GET | `/groups/my` | 我的群聊列表（部门群 + 全员群） |
| 8 | GET | `/groups/dept/messages` | 部门群历史消息 |
| 9 | POST | `/groups/dept/messages` | 发送部门群消息 |
| 10 | GET | `/groups/all/messages` | 全员群历史消息 |
| 11 | POST | `/groups/all/messages` | 发送全员群消息 |

### 4.3 接口详解

**7. GET `/groups/my`** — 我的群聊列表
- 成功 `200`：`{"groups": [...]}`，每个群对象字段：
  ```json
  {"group_type": "DEPT", "group_id": 60, "name": "部门群·IT", "member_count": 6,
   "last_message": "...", "last_time": "2026-08-21 12:00:00"}
  ```
  - `group_type`：`DEPT`（部门群）/ `ALL`（全员群）；部门群成员数=本部门人数，全员群=全体职员数
  - `last_message` / `last_time`：最近一条消息内容与时间（无消息时为 `null`）
- 说明：部门群自动包含（只要已分配部门），全员群固定返回

**8/10. GET `/groups/dept|all/messages`** — 群聊历史消息
- 参数：`page`、`page_size`
- 成功 `200`：`{"total": 12, "items": [消息对象, ...]}`（按时间**升序**；消息对象见「四、数据对象 · 消息对象」）
- 特殊：部门群自动取**当前用户所在部门**；未分配部门时部门群历史 `400`「您未分配部门,无法查看部门群」

**9/11. POST `/groups/dept|all/messages`** — 发送群消息
- body：`{content}`（1~2000 字）
- 成功 `200`：`{message_id, created_at}`
- 失败：被禁言 `403`「您已被禁言,暂时无法在群聊中发言」；部门群未分配部门 `400`

## 五、模块三：私聊

### 5.1 模块功能

> 本模块提供职员间**一对一私聊**全流程：选择联系人（可私聊的全体职员，不含本人）、获取与某人的私聊历史、发送私聊消息、按联系人维护会话列表（含每条会话的最近消息与未读数，**最近活跃会话自动置顶**）、标记已读，以及汇总全部会话的未读总数（供侧边栏红点提示）。私聊**不受禁言限制**，且发送方每发一条消息，接收方对应会话的未读数 +1。

### 5.2 接口一览

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 12 | GET | `/contacts` | 可私聊职员列表 |
| 13 | GET | `/private/messages` | 与某职员的私聊历史 |
| 14 | POST | `/private/messages` | 发送私聊 |
| 15 | GET | `/private/conversations` | 私聊会话列表（含未读数，新消息置顶） |
| 16 | POST | `/private/read` | 标记与某职员的会话已读 |
| 17 | GET | `/private/unread-total` | 未读私聊总数（侧边栏红点） |

### 5.3 接口详解

**12. GET `/contacts`** — 可私聊职员列表
- 成功 `200`：`[{EMPLOYEE_ID, name, DEPARTMENT_ID, role, avatar}]`
- 说明：返回除本人外的**全部职员**，按编号升序，供选择聊天对象

**13. GET `/private/messages`** — 与某职员的私聊历史
- 参数：`contact_id`（对方编号）、`page`、`page_size`
- 成功 `200`：`{total, items}`（双方往来消息，按时间升序，`items` 为消息对象）

**14. POST `/private/messages`** — 发送私聊
- body：`{receiver_id, content}`（content 1~2000 字）
- 成功 `200`：`{message_id, created_at}`；发送后**接收方未读数 +1**
- 失败：给自己发 `400`「不能给自己发送私聊」；接收者不存在 `404`「接收者不存在」
- 说明：禁言**不影响**私聊发言

**15. GET `/private/conversations`** — 私聊会话列表
- 成功 `200`：会话数组，每个会话对象：
  ```json
  [{"EMPLOYEE_ID": 103, "name": "Alexander Hunold", "avatar": null, "role": "STAFF",
    "DEPARTMENT_ID": 60, "last_message": "在吗", "last_time": "2026-08-21 19:39:41", "unread_count": 2}]
  ```
- 说明：按 `last_time` **降序**（最近消息置顶）；`unread_count` 用于会话红点；会话对方已删除时 `name` 显示「已删除职员#编号」

**16. POST `/private/read`** — 标记会话已读
- body：`{contact_id}`
- 成功 `200`：`{message}`「已标记已读」（清除该会话未读记录，红点消失）

**17. GET `/private/unread-total`** — 未读私聊总数
- 成功 `200`：`{total}`（全部会话未读之和，供侧边栏「私聊」入口红点）

## 六、模块四：权限与纪律管理

### 6.1 模块功能

> 本模块由**禁言管理**与**总裁管理**两部分组成，负责系统的纪律约束与权限体系维护：
>
> - **禁言管理（管理层）**：管理层可查看当前处于禁言状态的职员、对职员发起禁言（可设时长或永久）、解除禁言，用于约束群聊发言纪律。操作范围受限：管理部门职员仅可禁言普通职员，总裁可禁言管理层以下，均不可操作本人/总裁。
> - **总裁管理（仅总裁）**：唯一由总裁持有的权限，用于任免管理部门职员——查看管理部门名单、授予普通职员管理权限、撤销管理权限，构成系统的层级权限金字塔（总裁 → 管理部门 → 普通职员）。

### 6.2 接口一览

| # | 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|---|
| 18 | GET | `/mutes` | 禁言列表 | 管理层 |
| 19 | POST | `/mutes` | 禁言 | 管理层 |
| 20 | DELETE | `/mutes/{mute_id}` | 解除禁言 | 管理层 |
| 21 | GET | `/managers` | 管理部门职员名单 | 总裁 |
| 22 | POST | `/managers` | 授予管理权限 | 总裁 |
| 23 | DELETE | `/managers/{employee_id}` | 撤销管理权限 | 总裁 |

### 6.3 接口详解

#### 禁言管理（18~20，管理层）

**18. GET `/mutes`** — 禁言列表
- 成功 `200`：**当前生效中**（未过期且未解除）的禁言记录数组（见「四、数据对象 · 禁言对象」），按 `mute_id` 倒序

**19. POST `/mutes`** — 禁言
- body：`{employee_id, reason, mute_minutes?}`
  - `mute_minutes` 空 = **永久禁言**；填正整数 = 按分钟计算截止时间
- 成功 `200`：`{mute_id, message}`「已禁言 XX」
- 失败：被禁言职员不存在 `404`；越权 `403`（不能操作本人；管理部门仅可禁言普通职员；总裁不可禁言总裁/本人）

**20. DELETE `/mutes/{mute_id}`** — 解除禁言
- 成功 `204`（无返回体）；记录不存在 `404`「禁言记录不存在」

#### 总裁管理（21~23，总裁）

**21. GET `/managers`** — 管理部门职员名单
- 成功 `200`：`[{EMPLOYEE_ID, name, role, DEPARTMENT_ID}]`（`role` 为 `MANAGER` 或 `PRESIDENT`）

**22. POST `/managers`** — 授予管理权限
- body：`{employee_id}`
- 成功 `200`：`{message}`「已将 XX 授予为管理部门职员」
- 失败：职员不存在 `404`；目标已是管理层 `400`「该职员已是管理部门职员」；目标为总裁 `400`「不能对总裁操作」

**23. DELETE `/managers/{employee_id}`** — 撤销管理权限
- 成功 `200`：`{message}`「已撤销 XX 的管理权限」（目标降为 `STAFF`）
- 失败：职员不存在 `404`；目标不是管理层 `400`「该职员不是管理部门职员」；总裁 `400`「不能撤销总裁的管理权限」

## 七、模块五：员工管理与统计

### 7.1 模块功能

> 本模块面向**管理层**提供对组织数据（员工、部门、职位）的完整管理与可视化统计：
>
> - **员工增删改查**：新增普通职员（后端自动生成编号、账号=姓名、初始密码 `123456`、角色 `STAFF`）、更新、删除、按 ID 查询；操作受管理范围约束（管理部门仅可操作普通职员，总裁可含管理层）。
> - **组合查询**：多条件（姓名关键字/名/姓/部门/职位/薪资区间/入职日期区间）AND 过滤 + 分页，`keyword` 内部对 名/姓/邮箱 取 OR。
> - **基础字典**：部门列表、职位列表，供前端下拉框选择。
> - **仪表盘统计**：汇总员工总数、部门数、职位数、薪资极值/均值，并按部门、职位、入职年份三维度输出分布，驱动数据看板图表。

### 7.2 接口一览

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 24 | POST | `/employees` | 新增普通职员 |
| 25 | GET | `/employees` | 基础分页员工列表 |
| 26 | GET | `/employees/search` | 组合条件查询（分页） |
| 27 | GET | `/employees/{id}` | 按 ID 查询员工 |
| 28 | GET | `/find/{name}` | 姓名模糊查找 |
| 29 | PUT | `/employees/{id}` | 更新员工信息 |
| 30 | DELETE | `/employees/{id}` | 删除员工 |
| 31 | GET | `/departments` | 部门列表 |
| 32 | GET | `/jobs` | 职位列表 |
| 33 | GET | `/overview` | 仪表盘总览统计 |

### 7.3 接口详解

**24. POST `/employees`** — 新增普通职员
- body：员工公共字段（`FIRST_NAME`、`LAST_NAME`、`EMAIL`、`PHONE_NUMBER`、`HIRE_DATE`、`JOB_ID`、`SALARY`，可选 `COMMISSION_PCT`、`MANAGER_ID`、`DEPARTMENT_ID`）
- 成功 `201`：员工对象（含自动生成的 `EMPLOYEE_ID`、`ROLE=STAFF`、`AVATAR=null`）
- 说明：后端自动生成编号（当前最大编号+1）、账号=姓名、初始密码 `123456`；**姓名重复 `400`「姓名已存在,账号需唯一」**

**25. GET `/employees`** — 基础分页员工列表
- 参数：`skip`（偏移，默认 0）、`limit`（条数，默认 20）
- 成功 `200`：员工对象数组

**26. GET `/employees/search`** — 组合条件查询（分页）
- 参数：`keyword`（名/姓/邮箱模糊，内部 OR）、`first_name`、`last_name`、`department_id`、`job_id`、`min_salary`、`max_salary`、`hire_date_start`、`hire_date_end`、`page`、`page_size`
- 条件间为 **AND** 关系；`keyword` 仅与名/姓/邮箱匹配
- 成功 `200`：`{total, page, page_size, items}`（items 含 `ROLE`、`AVATAR`）
- 排序：按 `EMPLOYEE_ID` 升序

**27. GET `/employees/{id}`** — 按 ID 查询员工
- 成功 `200`：员工对象；不存在 `404`「员工不存在」

**28. GET `/find/{name}`** — 姓名模糊查找
- 路径参数 `name` 匹配 `FIRST_NAME`（模糊 LIKE）
- 成功 `200`：员工对象数组（可能为空）

**29. PUT `/employees/{id}`** — 更新员工信息
- body：与新增相同但**全部可选**，只更新传入字段
- 成功 `200`：更新后的员工对象；不存在 `404`；越权 `403`（不能操作本人/越级）

**30. DELETE `/employees/{id}`** — 删除员工
- 成功 `204`（无返回体）；不存在 `404`；越权 `403`（操作范围同上）

**31/32. GET `/departments`、`/jobs`** — 部门/职位字典
- 成功 `200`：部门列表（`DEPARTMENT_ID`、`DEPARTMENT_NAME` 等）/ 职位列表（`JOB_ID`、`JOB_TITLE`、薪资区间等），均按 ID 排序

**33. GET `/overview`** — 仪表盘总览统计
- 成功 `200`：
  ```json
  {"total_employees": 107, "total_departments": 11, "total_jobs": 19,
   "avg_salary": 8000.5, "max_salary": 20000, "min_salary": 3000,
   "department_stats": [{"department_id": 60, "department_name": "IT", "count": 6, "avg_salary": 9000}],
   "job_stats": [{"job_id": "AD_PRES", "job_title": "President", "count": 1}],
   "hire_year_distribution": [{"year": "2020", "count": 8}]}
  ```
- 说明：`department_stats` 含部门人数与平均薪资；`job_stats` 含职位人数；`hire_year_distribution` 为入职年份人数分布

## 八、数据对象

**用户对象（`/auth/me`、登录返回的 `user`、个人信息）**

| 字段 | 类型 | 说明 |
|---|---|---|
| EMPLOYEE_ID | int | 员工编号 |
| name | string | 姓名（即登录账号） |
| FIRST_NAME / LAST_NAME | string | 名 / 姓 |
| EMAIL / PHONE_NUMBER | string? | 邮箱 / 电话 |
| role | string | STAFF / MANAGER / PRESIDENT |
| avatar | string? | 头像路径 `/uploads/avatars/xxx.png` |
| JOB_ID | string? | 职位 ID |
| DEPARTMENT_ID | int? | 部门 ID |

**消息对象（群聊/私聊的 `items`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| message_id | int | 消息 ID |
| group_type / group_id | ? | 群聊为 DEPT/ALL 与群标识；私聊为 null |
| sender_id | int | 发送者编号 |
| sender_name | string | 发送者姓名 |
