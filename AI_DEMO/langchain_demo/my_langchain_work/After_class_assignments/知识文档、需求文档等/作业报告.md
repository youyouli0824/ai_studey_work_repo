# 企业内部知识库 RAG 问答系统 —— 作业报告

## 一、项目业务场景

某制造型企业（以"华信精密制造有限公司"为例）拥有员工手册、考勤制度、差旅报销制度、奖惩制度等大量内部政策文档，员工遇到制度咨询、流程查询时需翻阅大量文档，效率极低，且行政/HR 反复被同类问题咨询。本项目基于 **LangChain 框架**构建知识库 RAG 问答原型：员工输入自然语言问题，系统先从企业内部制度文档中检索相关内容，再交给大模型（DeepSeek `deepseek-v4-flash`）基于检索上下文生成精准回答，并输出参考来源。系统通过提示词指令**强制基于检索上下文回答，抑制大模型幻觉**，减少人工咨询成本。

## 二、RAG 执行流程（伪代码）

**离线阶段（build_knowledge.py）——知识库构建**：

```
for url in KNOWLEDGE_URLS:                        # 知识源：本地制度文档 + 企业政策网页
    docs = 加载知识源(过滤导航/广告，只提取正文)      # WebBaseLoader + SoupStrainer
chunks = RecursiveCharacterTextSplitter(docs,     # 语义分块 chunk_size=300 重叠50
          chunk_size=300, chunk_overlap=50)
vector = 分批向量化并入库(chunks, embeddings)       # 嵌入模型 → FAISS（merge_from 合并）
vector.save_local("faiss_store")                  # 向量库持久化
```

**在线阶段（rag_chat.py）——检索问答**：

```
vector_store = FAISS.load_local("faiss_store", allow_dangerous_deserialization=True)
retriever   = vector_store.as_retriever(k=3)       # 检索器
prompt      = ChatPromptTemplate(system=幻觉约束指令, human="{context}{input}")
doc_chain   = create_stuff_documents_chain(llm, prompt)   # 文档合并链
rag_chain   = create_retrieval_chain(retriever, doc_chain) # 组装检索链

用户问题 → retriever 召回 top-k 相关文档片段
       → 填充 prompt 上下文 → LLM 基于上下文生成答案
       → 输出 ①模型答案 ②参考来源(网页url/文件路径)
```

## 三、课堂核心知识点落地位置

| 课堂知识点 | 代码落地位置 |
| ---------- | ------------ |
| LangChain 积木式组件、可组合 | 项目拆分为 `embeddings.py`、`build_knowledge.py`、`rag_chat.py`、`prompt_demo.py`，各功能封装独立函数 |
| 大模型调用 ChatOpenAI | `embeddings.py` 的 `get_llm()`，密钥/base_url/模型名从 `.env` 读取（`load_dotenv`） |
| 网页文档加载 WebBaseLoader | `build_knowledge.py` 的 `load_web_documents()`，`SoupStrainer` 只提取正文容器 |
| 递归文本分割 RecursiveCharacterTextSplitter | `build_knowledge.py` 的 `split_documents()` |
| Embedding 嵌入模型 | `embeddings.py` 的 `get_embeddings()`（本地 bge 模型 / DashScope 可切换） |
| FAISS 本地向量库 | `build_knowledge.py` `build_faiss_store()` 保存；`rag_chat.py` `load_vector_store()` 加载 |
| RAG 检索链 stuff + retrieval | `rag_chat.py` 的 `build_rag_chain()`：`create_stuff_documents_chain` + `create_retrieval_chain` |
| 聊天提示模板 ChatPromptTemplate | `rag_chat.py` 全局 `RAG_PROMPT`（system 幻觉约束 + human 上下文/问题） |
| 字符串提示模板 PromptTemplate | `prompt_demo.py` 的 `summarize_with_prompt_template()`（文档摘要） |
| 少样本提示模板 FewShotPromptTemplate | `prompt_demo.py` 的 `process_steps_with_fewshot()`；`rag_chat.py` 的流程类问答 `PROCESS_PROMPT` |
| 环境变量管理 python-dotenv | 所有模块 `load_dotenv()`，密钥/模型/url 全部在 `.env`，无硬编码密钥 |

## 四、遇到的问题与解决思路

1. **FAISS 反序列化报错**：加载本地向量库时，LangChain 为安全考虑默认禁止加载 pickle 文件，报"unsafe pickle"。解决：`FAISS.load_local(..., allow_dangerous_deserialization=True)`，同时注释说明仅用于可信本地文件；向量库缺失时给出"请先运行 build_knowledge.py"的友好提示。
2. **提示词占位符错误**：`FewShotPromptTemplate` 的 `input_variables` 必须覆盖 `suffix` 中全部变量。初版把 `{context}` 加入 suffix 却未声明，运行时报"input variables 缺失"。解决：流程问答的 `input_variables=["context","question"]` 与 suffix 保持一致。
3. **检索链取 retriever 报错**：`create_retrieval_chain` 返回的是 `RunnableSequence`，没有 `.retriever` 属性。解决：`build_rag_chain()` 同时返回 `(retrieval_chain, retriever)`，流程问答直接复用检索器。
4. **嵌入模型联网失败 401**：`LOCAL_EMBED_MODEL` 用相对路径，从项目目录之外运行时会当成 HF 仓库名去 huggingface 下载（被墙报 401）。解决：`embeddings.py` 的 `resolve_project_path()` 将相对路径锚定到项目根目录；并从 hf-mirror 镜像下载 `bge-small-zh-v1.5` 到本地离线加载。
5. **知识源答不了业务问题**：初版知识源（燃气/热力公司手册）不含差旅报销、考勤细则等条款，回答"报销差旅费流程"等返回"未查询到"。解决：新增内容完整的制造型企业制度汇编作为主要知识源，并避免混入多公司制度导致规则冲突（如事假 20 天与 30 天并存），保证回答一致、有据可依。
