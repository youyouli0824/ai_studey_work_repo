# 企业内部知识库 RAG 问答系统 —— 使用文档

基于 **LangChain 开发框架**构建的企业内部知识库 RAG 问答原型系统。业务场景为**某制造型企业**，系统基于该企业内部政策文档（员工手册、考勤请假、差旅报销、加班调休、奖惩等制度）给出精准回答，减少人工咨询成本。

> 调用大模型：**DeepSeek `deepseek-v4-flash`**（通过 OpenAI 兼容接口）
> 文本嵌入：本地 **`bge-small-zh-v1.5`** 中文嵌入模型（离线可用，无需额外密钥）

---

## 一、项目结构

项目位于 `work/` 目录：

```
work/
├── .env                      # 环境变量（含 DeepSeek 密钥，勿提交仓库）
├── .env.example              # 环境变量模板
├── requirements.txt          # 依赖清单
├── embeddings.py             # 共享模型工厂：LLM + 嵌入模型（积木式组件）
├── build_knowledge.py        # 模块1：知识库构建（网页加载→分块→向量化→FAISS入库）
├── rag_chat.py               # 模块2：RAG 检索问答（通用问答 + 流程类问答）
├── prompt_demo.py            # 模块3：三类提示词模板演示
├── models/bge-small-zh-v1.5/ # 本地中文嵌入模型（离线加载）
├── data/enterprise_policies.html # 制造型企业制度汇编（内置知识源样例，含考勤/请假/差旅报销/加班/奖惩/保密/离职）
├── faiss_store/              # FAISS 向量库（运行 build_knowledge.py 自动生成）
└── readme.md                 # 简明运行说明
```

> 知识源构成：`data/enterprise_policies.html`（主要，制造型企业制度汇编样例，可替换为本公司真实制度文档）+ 夏津燃气员工手册（真实企业网页，用于演示 WebBaseLoader 网页加载）。

## 二、环境搭建

### 1. 创建虚拟环境（可选但推荐）

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

### 2. 安装依赖

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3. 配置 `.env`

复制 `.env.example` 为 `.env`，填入真实密钥：

```bash
API_KEY=你的 DeepSeek API 密钥        # 必填
BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-v4-flash           # 对话模型
EMBED_PROVIDER=local                  # 嵌入方案：local（本地）/ dashscope（阿里云）
LOCAL_EMBED_MODEL=models/bge-small-zh-v1.5
# 知识库来源：本地制度文档 + 企业政策网页（多个用英文逗号分隔）
KNOWLEDGE_URLS=data/enterprise_policies.html,http://www.xiajin.gov.cn/n31121413/n44484126/n44486980/...
# 网页正文容器 class（多个候选用 | 分隔，程序自动选用提取内容最多的那个）
CONTENT_SELECTOR=article-content|p-2 text-justify
```

> ⚠️ `.env` 包含真实密钥，已被 `.gitignore` 忽略，切勿提交到代码仓库。

## 三、运行顺序

| 顺序 | 命令 | 作用 |
| ---- | ---- | ---- |
| 1 | `python build_knowledge.py` | 构建知识库（生成 `faiss_store`） |
| 2 | `python rag_chat.py` | RAG 检索问答（交互式） |
| 3 | `python prompt_demo.py` | 三类提示词模板演示 |

> 每次修改 `KNOWLEDGE_URLS` 或知识源内容后，需重新运行第 1 步重建向量库。
> 提示：脚本内部已按「项目根目录」解析本地模型与向量库路径，因此也可以**在任何目录**通过完整路径运行，例如 `python D:/.../work/build_knowledge.py`，结果一致。

## 四、功能说明

### 模块1：知识库构建（build_knowledge.py）

离线路程：**知识源加载（WebBaseLoader / 本地制度文档） → RecursiveCharacterTextSplitter 分块 → 文本向量化 → FAISS 本地入库**。

- 知识源支持两种形式：
  - **本地制度文档**：`data/enterprise_policies.html`（制造型企业制度汇编，内容最全），直接解析本地 HTML；
  - **真实企业网页**：使用 `WebBaseLoader` 抓取（如夏津燃气员工手册），演示网页加载；
- 使用 BeautifulSoup 的 `SoupStrainer` 只提取网页正文容器，过滤导航、广告等无关标签；
- 不同网站正文容器 class 不同，`CONTENT_SELECTOR` 支持配置多个候选 class（用 `|` 分隔），程序自动为每个网页选用提取内容最多的那个，全部无效时回退提取整页；
- 按 `chunk_size=300 / chunk_overlap=50` 语义分块，块间保留重叠防止语义断裂；
- 大批量文档采用「分批向量化 + `merge_from` 合并索引」方式入库；
- 加载、分块、向量化、存储拆分为独立函数，体现积木式开发思想。


### 模块2：RAG 检索问答（rag_chat.py）

- 加载本地 FAISS 向量库（`allow_dangerous_deserialization=True`）；
- 使用 **ChatPromptTemplate** 聊天模板（system 角色做幻觉约束 + human 角色传问题）构建 RAG 提示词；
- `create_stuff_documents_chain` 文档合并链 + `create_retrieval_chain` 组装完整 RAG 检索链；
- 输出两部分：**① 模型最终答案 ② 检索到的参考文档来源（网页 URL）**。

**支持的输入**：

| 输入 | 走哪个模板 | 说明 |
| ---- | ---------- | ---- |
| 直接输入问题 | ChatPromptTemplate | 通用制度问答 |
| `流程：<问题>` | FewShotPromptTemplate | 流程类问答，强制输出 `1.xxx\n2.xxx` 步骤列表 |
| `quit` / `exit` | - | 退出系统 |

**幻觉抑制**：system 指令强制「只允许根据检索上下文回答，没有相关资料直接回复『知识库未查询到相关制度』，禁止编造内容」。

## 五、课堂知识点落地对照

| 课堂核心知识点 | 项目落地位置 |
| -------------- | ------------ |
| LangChain 组件可组合、积木式开发 | 项目拆分独立模块/函数：`embeddings.py`、各功能函数，无硬编码胶水代码 |
| 大模型调用 ChatOpenAI | `embeddings.py` `get_llm()`，读取 `.env` 配置 DeepSeek，不硬编码密钥 |
| 网页文档加载 WebBaseLoader | `build_knowledge.py` `load_web_documents()`，`SoupStrainer` 过滤无关标签 |
| 文本分割 RecursiveCharacterTextSplitter | `build_knowledge.py` `split_documents()`，`chunk_size/chunk_overlap` |
| Embedding 嵌入模型 | `embeddings.py` `get_embeddings()`（本地 bge / DashScope 可切换） |
| FAISS 本地向量数据库 | `build_knowledge.py` `build_faiss_store()`；`rag_chat.py` `load_vector_store()` |
| RAG 检索链（stuff + retrieval） | `rag_chat.py` `build_rag_chain()`，`create_stuff_documents_chain + create_retrieval_chain` |
| 聊天提示模板 ChatPromptTemplate | `rag_chat.py` 全局 `RAG_PROMPT`（system+human 角色消息） |
| 字符串提示模板 PromptTemplate | `prompt_demo.py` `summarize_with_prompt_template()` |
| 少样本提示模板 FewShotPromptTemplate | `prompt_demo.py` `process_steps_with_fewshot()`；`rag_chat.py` 流程类问答 |
| 环境变量管理 python-dotenv | 所有模块 `load_dotenv()`，密钥/模型/URL 全部在 `.env` |

## 六、常见问题

**Q1：运行 rag_chat.py 提示「未找到向量库目录」？**
→ 先运行 `python build_knowledge.py` 构建知识库，再运行问答。

**Q2：没有 DeepSeek API 密钥 / 密钥错误？**
→ 到 `.env` 配置 `API_KEY`；密钥错误时接口会返回认证失败提示。

**Q3：想用阿里云 DashScope 嵌入（课程原方案）？**
→ `.env` 设置 `EMBED_PROVIDER=dashscope` 并配置 `DASHSCOPE_API_KEY`，代码已内置该分支。

**Q4：想更换/扩充知识库内容？**
→ 修改 `.env` 的 `KNOWLEDGE_URLS`（多个用英文逗号分隔），支持两种来源：
- **本地制度文档**：填入 `data/xxx.html` 等本地 HTML 路径，可直接修改 `data/enterprise_policies.html` 增删制度条款；
- **真实企业网页**：填入 `http(s)://` 地址（如夏津员工手册），若正文容器 class 与当前配置不同，在 `CONTENT_SELECTOR` 中追加（多个候选用 `|` 分隔），程序自动选用提取内容最多的那个。
改完重新运行 `build_knowledge.py` 重建知识库即可。

**Q5：回答质量不理想？**
→ 调整 `.env` 的 `RETRIEVER_K`（检索条数，默认 3）或在 `split_documents()` 调整 `chunk_size/chunk_overlap`。

**Q6：运行时报错 401 Repository Not Found / 找不到本地模型？**
→ 早期版本的模型路径是相对路径，从项目目录之外运行会找不到模型而去联网下载。请确保代码中 `resolve_project_path()`（`embeddings.py`）已生效，模型路径会锚定到项目根目录的 `models/bge-small-zh-v1.5`，任何目录运行均可。

**Q7：启动时提示 langchain-community 将被弃用（DeprecationWarning）？**
→ 这是正常的提示。`WebBaseLoader`、`FAISS` 等课程要求使用的组件来自 `langchain-community`，该包仍可正常使用，只是官方计划迁移到独立包。不影响项目运行，可忽略。
