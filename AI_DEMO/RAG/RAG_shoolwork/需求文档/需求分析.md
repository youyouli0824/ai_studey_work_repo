## 1. 项目概述

### 1.1 项目名称
企业人事制度知识库问答系统（私有化 RAG 检索增强生成问答系统）。

### 1.2 项目定位
本项目为《RAG检索增强生成》课程项目作业，围绕"企业内部人事制度知识库问答"这一真实业务场景，完整实现 RAG（Retrieval-Augmented Generation）检索增强生成技术链路，用于解决通用大模型在企业私有知识问答场景下的核心问题：**幻觉、知识断层、领域知识不足**。

### 1.3 项目背景
某科技公司（汇视威）内部存在大量制度文档（人事管理制度、考勤作息、入职转正、招聘流程等 docx 文件）。员工与行政人事部门在制度咨询上存在以下矛盾：

- 员工频繁咨询制度，直接调用通用大模型会产生幻觉，编造不存在的公司制度；
- 公司制度持续迭代更新，大模型训练知识存在时间断层，无法获取企业私有最新内部规则；
- 制度文档篇幅长，人工翻阅 Word 文档查找规则效率低下；
- 企业不希望将内部制度上传至公有知识库，要求支持本地 Embedding 与在线 Embedding 的兼容能力；
- 简单检索容易召回无关片段，需要引入重排（Rerank）优化检索结果质量。

### 1.4 项目目标
构建一套**企业私有 RAG 知识库问答系统**，达成以下目标：

1. 员工输入自然语言问题，系统基于本地人事制度文档给出准确回答；
2. 制度文档更新后，可重新构建知识库索引（进阶要求支持增量更新）；
3. 尽可能抑制大模型幻觉：知识库中没有的内容，系统必须明确回复"不知道"，禁止编造答案；
4. 完整覆盖课程全部核心知识点，实现离线索引、检索生成两大阶段；
5. 同时支持本地 Embedding 模型与在线 API Embedding 两种模式；
6. 进阶实现重排（Rerank）后处理，过滤无关片段，提升检索质量。

### 1.5 项目范围

| 范围 | 说明 |
| --- | --- |
| 范围之内 | docx 文档加载、文档切分、向量化、向量入库、余弦相似度检索、Prompt 组装、LLM 生成回答、本地/在线 Embedding 切换、Rerank 重排（进阶）、增量更新（进阶） |
| 范围之外 | 前端 Web 界面、用户登录鉴权、多租户管理、大模型权重文件分发（权重文件不纳入交付） |

## 2. 业务需求分析

### 2.1 目标用户

| 用户角色 | 需求描述 |
| --- | --- |
| 普通员工 | 通过自然语言查询人事制度（转正流程、入职材料、考勤作息等），快速获得准确答案 |
| 行政人事 / 知识库管理员 | 维护制度文档，更新知识库索引，保证问答内容与最新制度一致 |
| 开发 / 运维人员 | 运行、调试、扩展系统，切换本地/在线 Embedding，排查幻觉问题 |

### 2.2 典型使用场景（用户故事）

- **场景 A（知识库内问题）**：员工问"转正流程是什么？"，系统应基于《入职转正制度》文档准确回答转正步骤。
- **场景 B（知识库内问题）**：员工问"入职需要提交哪些资料？"，系统应列出入职材料清单。
- **场景 C（知识库内问题）**：员工问"早班几点上班？"，系统应依据《考勤作息制度》给出具体时间。
- **场景 D（知识库外问题）**：员工问"公司年终奖发放规则是什么？"，若知识库无相关内容，系统必须回复"不知道"，检验幻觉抑制效果。
- **场景 E（文档更新）**：制度文档更新后，管理员重新构建/增量更新索引，新制度即可被检索到。

### 2.3 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 回答必须严格基于检索到的知识库片段，禁止使用大模型自身知识编造答案 |
| BR-02 | 当知识库中不存在对应信息时，系统必须回复"不知道" |
| BR-03 | 知识库只加载企业本地 docx 制度文档，不连接外部公有知识库 |
| BR-04 | 制度文档变更后，索引可重建（基础）或增量更新（进阶） |

## 3. 功能需求

功能需求分为 **基础功能（必做，Naive RAG）** 与 **进阶功能（选做，Advanced RAG）** 与 **拓展思考（选做，Modular RAG，仅报告）** 三个层次。

### 3.1 文档加载模块（FR-01）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 读取本地 docx 格式的企业人事制度文档，完成文档加载 |
| 输入 | 本地 docx 文件路径（可为目录，加载目录下全部 docx） |
| 输出 | 加载成功的文档对象（文档元数据 + 正文文本） |
| 处理逻辑 | 遍历指定目录，识别 `.docx` 文件并解析正文，记录文档名、来源路径等元数据 |
| 异常处理 | 文档路径不存在、文件无法解析时给出明确错误提示，不中断其他文档加载 |
| 验收标准 | 能成功加载至少一份人事制度 docx 文档并打印文档块数量 |

### 3.2 文档切分模块（FR-02）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 采用滑动窗口递归切分（Recursive Character Text Splitter / SentenceSplitter），对长文档进行切分 |
| 输入 | 文档正文文本 + 切分参数 |
| 可配置参数 | `CHUNK_SIZE`（文本块大小）、`CHUNK_OVERLAP`（滑动窗口重叠长度） |
| 输出 | 若干个文本块（Node/Chunk），每个块保留源文档元数据 |
| 处理逻辑 | 递归按段落/句子/字符切分，窗口滑动保留 overlap，避免语义断裂 |
| 验收标准 | 支持配置 `chunk_size`、`chunk_overlap`；报告中对不同切分策略的效果差异进行对比 |

### 3.3 Embedding 向量化模块（FR-03）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 将文本块转换为向量，支持本地模型与在线 API 两种模式 |
| 本地模式 | 默认使用 `bge-large-zh-v1.5` 本地模型完成向量化，离线环境可运行 |
| 在线模式 | 支持 DeepSeek / 阿里云 dashscope 在线 Embedding API 调用 |
| 切换方式 | 通过配置开关 `USE_LOCAL_EMBED` 与 `EMBED_MODEL_PATH` 切换 |
| 输出 | 文本块向量（Embedding），并在日志中打印向量维度 |
| 验收标准 | 两种模式均可正常运行并输出向量；报告说明本地/在线模式使用体验差异 |

### 3.4 向量库存储模块（FR-04）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 将文本块及其向量持久化存入向量数据库 |
| 技术选型 | LlamaIndex 内置向量存储，Faiss 或 Chroma 二选一 |
| 输出 | 向量索引持久化文件 |
| 进阶要求 | 支持加载已有索引，避免每次启动都重建索引 |
| 验收标准 | 向量入库成功；进阶实现持久化保存与加载已有索引 |

### 3.5 检索模块（FR-05）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 对用户 query 向量化，基于余弦相似度检索 top-K 相关文档片段 |
| 输入 | 用户自然语言问题 + `SIM_TOP_K` 参数 |
| 输出 | top-K 个候选文档片段及其相似度分数 |
| 相似度算法 | 使用向量库底层余弦相似度检索（报告需说明余弦相似度原理） |
| 验收标准 | 能返回与问题相关的文档片段；进阶打印余弦相似度分数 |

### 3.6 重排模块（FR-06，进阶）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 接入本地 `bge-reranker-base` 重排模型，对检索返回的 top-K 节点做重排后处理 |
| 输入 | 检索返回的 top-K 候选片段 |
| 输出 | 按相关性重排后的 top-N 片段（`RERANK_TOP_N`），过滤低相关性片段 |
| 验收标准 | Rerank 开启前后问答效果有可观测对比（报告需体现对比结论） |

### 3.7 回答生成模块（FR-07）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 自定义 Prompt 模板，结合检索到的上下文，调用 DeepSeek 大模型生成回答 |
| 输入 | 用户问题 + 检索/重排后的上下文片段 |
| 输出 | 大模型生成的回答 + 召回的原始文档片段（便于排查幻觉） |
| Prompt 约束 | 强制要求：若知识库没有对应信息，直接回复"不知道"，禁止编造答案 |
| 验收标准 | 知识库内问题回答准确；知识库外问题回复"不知道"；同时打印召回片段 |

### 3.8 增量更新模块（FR-08，进阶）

| 项 | 内容 |
| --- | --- |
| 功能描述 | 支持增量更新知识库：新增制度文档，无需重建全部索引 |
| 输入 | 新增的 docx 文档 |
| 输出 | 更新后的向量库（新增文档已入库） |
| 验收标准 | 新增文档后无需全量重建即可被检索到 |

### 3.9 功能需求优先级汇总

| 编号 | 功能 | 优先级 | 备注 |
| --- | --- | --- | --- |

## 5. 系统架构与流程

### 5.1 总体架构

系统采用经典的 **RAG 两大阶段** 结构，线性流水线（Naive RAG）为基础，进阶增加 Rerank 后处理（Advanced RAG），拓展思路升级为 Modular RAG。

```
┌─────────────────────────── 离线索引阶段（Offline Indexing）───────────────────────────┐
│  文档加载(docx)  →  文档切分(滑动窗口递归切分)  →  Embedding向量化  →  向量库入库        │
│                              (本地 bge / 在线 API)          (Faiss/Chroma 持久化)       │
└─────────────────────────────────────────────────────────────────────────────────────────┘
                                        │
                                        ▼
┌─────────────────────────── 检索生成阶段（Retrieval & Generation）──────────────────────┐
│  query  →  query向量化  →  top-K 余弦相似度检索  →  [Rerank 重排]  →  Prompt组装        │
│                                                   (进阶 bge-reranker)                    │
│        →  DeepSeek LLM 生成回答  →  输出回答 + 召回片段                                  │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 离线索引阶段流程

1. **文档加载**：遍历本地目录，解析全部 `.docx` 文档。
2. **文档切分**：按 `chunk_size`、`chunk_overlap` 滑动窗口递归切分为文本块。
3. **向量化**：根据 `USE_LOCAL_EMBED` 选择本地 BGE 模型或在线 API，将文本块转为向量。
4. **向量入库**：文本块 + 向量 + 元数据写入 Faiss/Chroma 向量库并持久化。

### 5.3 检索生成阶段流程

1. **Query 向量化**：将用户问题转为向量（与索引阶段使用同一 Embedding 模型）。
2. **相似度检索**：余弦相似度计算，召回 top-K 个相关片段。
3. **重排（进阶）**：bge-reranker-base 对 top-K 片段重排序，取 top-N。
4. **Prompt 组装**：将问题 + 上下文片段 + 幻觉约束指令组装为 Prompt。
5. **LLM 生成**：调用 DeepSeek 大模型生成回答。
6. **结果输出**：输出回答，并打印召回的原始文档片段与相似度分数。

### 5.4 关键数据结构

- **文本块（Node/Chunk）**：`{ text, metadata: {source, ...}, embedding }`
- **配置项**：见第 7 章。

## 6. 接口与数据需求

### 6.1 系统输入

| 输入 | 类型 | 说明 |
| --- | --- | --- |
| 制度文档 | docx 文件（目录） | 企业人事管理制度、考勤作息、入职转正、招聘流程等 |
| 用户问题 | 自然语言文本 | 如"转正流程是什么？""早班几点上班？""入职需要提交哪些资料？" |

### 6.2 系统输出

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| 大模型回答 | 文本 | 基于知识库生成的准确回答，或"不知道" |
| 召回片段 | 文本列表 | 检索命中的原始文档片段（用于调试与排查幻觉） |
| 相似度分数 | 数值 | 各召回片段的余弦相似度分数（进阶打印） |
| 关键日志 | 控制台输出 | 文档块数量、向量维度、召回片段、相似度分数 |

### 6.3 外部依赖接口

| 接口 | 用途 | 说明 |
| --- | --- | --- |
| DeepSeek API | LLM 生成回答 | 需 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` |
| 在线 Embedding API | 在线向量化（可选） | 支持 DeepSeek / 阿里云 dashscope |
| 本地 BGE 模型 | 本地向量化 | `bge-large-zh-v1.5` |
| 本地 Rerank 模型 | 重排（进阶） | `bge-reranker-base` |

## 7. 配置项需求

所有配置统一由 `.env` 文件管理，禁止硬编码。配置项定义如下：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | （留空） | DeepSeek API 密钥 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | DeepSeek 接口地址 |
| `USE_LOCAL_EMBED` | `True` | 是否使用本地 Embedding（True=本地，False=在线） |
| `EMBED_MODEL_PATH` | `./models/BAAI/bge-large-zh-v1.5` | 本地 Embedding 模型路径 |
| `RERANK_MODEL_PATH` | `./models/BAAI/bge-reranker-base/snapshots/master` | 本地重排模型路径 |
| `CHUNK_SIZE` | `512` | 文本块大小 |
| `CHUNK_OVERLAP` | `50` | 滑动窗口重叠长度 |
| `SIM_TOP_K` | `6` | 检索召回数量 |
| `RERANK_TOP_N` | `3` | 重排后保留数量 |
| `VECTOR_DB_PATH` | `./vector_db` | 向量库持久化路径 |

## 8. 开发与工程规范

### 8.1 环境管理
- 使用虚拟环境（venv/conda）隔离依赖；
- 提供 `requirements.txt` 依赖清单；
- 使用 `.env` 统一管理 API Key、模型路径、参数。

### 8.2 代码结构
- 目录结构规范（工程目录分层清晰，可参考：数据加载、切分、向量化、入库、检索、重排、生成等模块划分）；
- 关键逻辑必须写注释，明确标注【离线索引阶段】【检索生成阶段】。

### 8.3 代码要求
- 参数解耦：`chunk_size`、`chunk_overlap`、`top_k` 全部从环境变量读取，不写死；
- 异常捕获：处理模型路径不存在、文档读取失败等异常；
- 禁止硬编码密钥；

## 11. 风险与约束

| 编号 | 风险/约束 | 应对措施 |
| --- | --- | --- |
| R-01 | 本地 reranker 模型 snapshots/master 路径陷阱 | 路径需指向真实模型权重目录，而非 soft link 目录 |
| R-02 | Windows 环境虚拟内存不足（报错 1455 页面文件太小） | 开启 `low_cpu_mem_usage=True`，或调整系统虚拟内存 |
| R-03 | Prompt 约束失效导致幻觉 | Prompt 模板严格约束：背景无信息即回复"不知道" |
| R-04 | 参数写死导致不可维护 | 所有关键参数从环境变量读取 |
| R-05 | 密钥泄露风险 | 禁止硬编码，`.env` 示例密钥留空 |
| R-06 | 索引重复构建耗时 | 进阶实现向量库持久化，加载已有索引 |
