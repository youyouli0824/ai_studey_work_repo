## 1. 总体流程

```
安装依赖 → 下载本地 BGE 模型 → 配置 .env → 构建索引 → 问答
                 （一次性）          （一次性）     （文档变更后重跑）
```

- **第一次运行**：1 → 2 → 3 → 4 → 5 → 6 → 7
- **之后再次运行**：只需要 7（问答），索引已持久化在 `vector_db/`，直接复用，无需重建。
- **制度文档更新后**：重新执行 6（`--rebuild` 全量重建）或使用增量更新（见第 8 节）。

## 2. 环境准备

### 2.1 Python 版本

建议 **Python 3.10 ~ 3.14**（本项目在 Windows + Python 3.14 实测通过）。

### 2.2 创建虚拟环境（推荐）

```bash
# 在项目根目录 myProject/ 下
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

### 2.3 安装依赖

```bash
python -m pip install -r requirements.txt
```

依赖清单（`requirements.txt`）包含：

| 依赖 | 用途 |
| --- | --- |
| `llama-index-core` | RAG 框架核心（Document、SentenceSplitter 切分） |
| `llama-index-vector-stores-chroma` | LlamaIndex 内置 Chroma 向量存储 |
| `chromadb` | 向量数据库（余弦检索、持久化） |
| `sentence-transformers` | 本地 bge 向量化 / bge-reranker 重排 |
| `torch` / `transformers` | 深度学习运行环境 |
| `openai` | DeepSeek 大模型、在线 Embedding 调用（OpenAI 兼容） |
| `python-docx` | docx 制度文档解析 |
| `python-dotenv` | `.env` 配置加载 |
| `numpy` | 数值计算 |

## 3. 下载本地模型

本地 BGE 模型（Embedding + Rerank）是离线运行的核心，第一次使用前需下载到 `models/` 目录。

```bash
# 下载全部（Embedding bge-large-zh-v1.5 + Rerank bge-reranker-base，约 2.4GB）
python scripts/download_models.py

# 只下载其中一个
python scripts/download_models.py --embed    # 只下载 Embedding 模型
python scripts/download_models.py --rerank   # 只下载 Rerank 模型
```

> **国内下载慢/失败**：先设置镜像再重试
> ```bash
> # Windows PowerShell
> $env:HF_ENDPOINT = "https://hf-mirror.com"
> # macOS / Linux
> export HF_ENDPOINT=https://hf-mirror.com
> python scripts/download_models.py
> ```

下载完成后模型位于：

```
models/
└── BAAI/
    ├── bge-large-zh-v1.5/     # 本地 Embedding 模型（1024 维）
    └── bge-reranker-base/     # 本地重排模型（Advanced-RAG 用）
```

> ⚠️ 模型权重文件较大，已在 `.gitignore` 中排除，不属于交付物。

## 4. 配置 .env

所有配置（API Key、模型路径、切分参数等）统一由项目根目录的 `.env` 文件管理，**禁止硬编码**。

```bash
# 复制模板
cp .env.example .env        # Windows CMD/PowerShell 用：copy .env.example .env
```

然后编辑 `.env`，至少填写：

```ini
# DeepSeek API Key（必填，问答生成需要）
DEEPSEEK_API_KEY=sk-你的密钥
```

其余配置项均可按需调整，常用项说明：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | （空） | **必填**，DeepSeek 密钥 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | DeepSeek 接口地址 |
| `USE_LOCAL_EMBED` | `True` | `True`=本地 BGE 向量化；`False`=在线 Embedding API |
| `EMBED_MODEL_PATH` | `./models/BAAI/bge-large-zh-v1.5` | 本地 Embedding 模型路径 |
| `USE_RERANK` | `True` | `True`=开启 bge-reranker 重排；`False`=关闭（对比实验） |
| `RERANK_MODEL_PATH` | `./models/BAAI/bge-reranker-base` | 重排模型路径 |
| `CHUNK_SIZE` | `512` | 滑动窗口切分文本块大小 |
| `CHUNK_OVERLAP` | `50` | 相邻文本块重叠长度 |
| `SIM_TOP_K` | `6` | 检索召回 top-K 片段数 |
| `RERANK_TOP_N` | `3` | 重排后保留片段数 |
| `DATA_DIR` | `./data` | 制度文档目录 |
| `VECTOR_DB_PATH` | `./vector_db` | 向量库持久化目录 |

> 🔒 `.env` 已加入 `.gitignore`，包含密钥不会提交到仓库。交付模板 `.env.example` 中的密钥已留空。

## 5. （可选）生成示例制度文档

项目自带 4 份示例制度文档（`data/*.docx`），开箱即用。

如需**重新生成**（或想恢复初始内容），执行：

```bash
python scripts/generate_sample_docs.py
```

生成内容：

| 文档 | 覆盖内容 |
| --- | --- |
| 人事管理制度.docx | 总则、入职、劳动合同、薪酬福利、培训、绩效、奖惩、离职 |
| 考勤作息制度.docx | 工作时间（早/中/晚班）、打卡、迟到早退、请假、加班调休 |
| 入职转正制度.docx | 入职资料、入职流程、试用期、转正流程 |

> 自定义制度：把你自己的 `.docx` 制度文档放入 `data/` 目录即可（支持子目录递归扫描），无需改代码。

## 6. 构建离线索引

### 6.1 首次构建 / 文档变更后全量重建

```bash
# 从 data/ 目录加载全部 docx，切分、向量化、入库
python scripts/build_index.py --rebuild
```

控制台会输出关键日志（验收指标）：

```
[文档加载] 成功：入职转正制度.docx（976 字符）
[文档切分] 递归+滑动窗口切分完成：chunk_size=512, chunk_overlap=50, 生成文本块 12 个
[Embedding] 本地模型加载完成，向量维度：1024
[向量库] 本次入库 12 块，当前文档块总数：12
[完成] 离线索引构建成功，向量库共 12 个文档块
```

### 6.2 增量构建（不重建全部索引）

向量库已有数据时，直接运行 `build_index.py`（不带 `--rebuild`）会复用旧索引，仅把 `data/` 下新增的文档追加入库。正式场景建议用第 8 节的 `update_index.py` 更明确。

## 7. 问答使用

### 7.1 命令行单条提问

```bash
python scripts/query.py "转正流程是什么？"
python scripts/query.py "入职需要提交哪些资料？"
python scripts/query.py "早班几点上班？"
```

### 7.2 交互问答模式

```bash
python scripts/query.py
```

```
进入交互问答模式（输入 exit 退出）

Q: 转正流程是什么？
...
Q: exit
```

### 7.3 输出说明

运行时会依次打印（便于排查幻觉）：

1. **检索阶段**：召回的 top-K 片段 + 来源文档 + **余弦相似度分数**
2. **重排阶段**（开启时）：重排后保留的 top-N 片段 + 重排分
3. **生成阶段**：DeepSeek 大模型回答

回答示例：

```
[检索] 召回的 top-6 片段：
  #1 来源:入职转正制度.docx 余弦相似度=0.5371 | 第五章 转正流程
  ...

[重排] bge-reranker 重排后保留 top-3 片段：
  #1 来源:入职转正制度.docx 重排分=0.9940 | 第五章 转正流程
  ...

[生成] DeepSeek 回答：
根据《汇视威科技 入职转正制度》第五章第九条，转正审批流程如下：
（一）试用期届满前 15 天，由员工本人填写《转正申请审批表》...
```

## 8. 进阶功能使用

### 8.1 重排开关对比（Advanced-RAG）

```bash
# 开启 Rerank（默认）
python scripts/query.py "转正流程是什么？"

# 关闭 Rerank（Naive-RAG，用于对比实验）
python scripts/query.py "转正流程是什么？" --no-rerank
```

也可在 `.env` 中改 `USE_RERANK=False` 全局关闭。

### 8.2 增量更新知识库（FR-08）

新增制度文档**无需重建全部索引**，直接入库：

```bash
# 指定一个或多个文件
python scripts/update_index.py data/新制度文档.docx
python scripts/update_index.py data/新制度1.docx data/新制度2.docx

# 或扫描某目录下的全部 docx
python scripts/update_index.py --dir data/新增目录
```

验证方法：更新前问"新制度相关问题"→ 回复"不知道"；执行增量更新后再问 → 已能检索回答。

### 8.3 切分策略对比实验（报告用）

```bash
python scripts/chunking_comparison.py
```

对比「固定字符切分 / 按标点切分 / 递归+滑动窗口切分」的块数、平均长度，以及 `chunk_size`、`chunk_overlap` 参数影响。

### 8.4 本地 / 在线 Embedding 切换

编辑 `.env`：

```ini
# 本地模式（默认，离线可用）
USE_LOCAL_EMBED=True

# 在线模式（改为 False，并配置在线密钥）
USE_LOCAL_EMBED=False
EMBED_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBED_API_KEY=sk-在线密钥
EMBED_API_MODEL=text-embedding-v3
```

> ⚠️ 本地 / 在线两种模式的向量空间不同，**切换后必须 `--rebuild` 重建索引**。

## 9. 常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 报错 `DEEPSEEK_API_KEY` 缺失 | `.env` 未配置密钥 | 复制 `.env.example` 为 `.env` 并填写 |
| 报错 `模型路径不存在` / 加载失败 | 模型未下载 | 执行 `python scripts/download_models.py` |
| 报错 `No module named 'docx'` 等 | 依赖未安装 | `python -m pip install -r requirements.txt` |
| 重排模型加载失败（snapshots/master） | 指向了软链目录 | 将 `RERANK_MODEL_PATH` 改为真实权重目录 `./models/BAAI/bge-reranker-base` |
| Windows 报错 1455 页面文件太小 | 虚拟内存不足 | 代码已开启 `low_cpu_mem_usage=True`；仍报错则增大系统虚拟内存或换更小批次 |
| 问知识库内的问题却答"不知道" | 索引未构建 / 文档未入库 | 执行 `python scripts/build_index.py --rebuild` |
| 切换 Embedding 模式后结果异常 | 向量空间不一致 | 切换后执行 `--rebuild` 重建索引 |
| 问题答案编造内容（幻觉） | Prompt 约束失效 / 上下文不相关 | 确认 `.env` 的 `SYSTEM_PROMPT` 未被覆盖；开启 Rerank 过滤无关片段 |
