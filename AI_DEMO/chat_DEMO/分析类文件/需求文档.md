# 职员各部门工作交流系统 — 需求文档

> 版本：V2.2 · 编写日期：2026-08-18 · 适用范围：前后端一体项目  
> 变更：V1.0「职工信息管理系统」（员工CRUD/查询/统计）→ V2.0 升级为办公交流平台（登录/角色/群聊/私聊/头像/禁言/总裁管理）→ V2.1 登录新增员工编号、删除无部门员工 → V2.2 私聊新增会话列表（未读红点、新消息置顶、标记已读）。

---

## 一、项目概述

- **背景**：原系统为员工数据可视化管理，无登录与角色体系。升级为全员使用的办公交流平台。
- **目标**：① 姓名/员工编号登录；② 三级角色按权限分面板；③ 个人中心 + 部门群聊/全员群聊/私聊；④ 管理层对普通职员增删改查、信息面板、禁言；⑤ 总裁管理管理部门并可授予/撤销管理权限。
- **范围内**：登录、角色权限、个人中心、部门群聊、全员群聊、私聊、员工管理、信息面板、禁言、总裁管理。
- **范围外（本期不做）**：实时推送（WebSocket，本期 5s 轮询）、已读回执、图片/附件/@ 消息、数据导出、审计日志。

**术语**：普通职员（基础角色）、管理部门职员（管理员，持管理功能）、总裁（最高角色，唯一）、部门群聊（同部门）、全员群聊（全部部门）、私聊（一对一）、禁言（限制群聊发言）。

## 二、角色与权限

| 角色 | 说明 |
|---|---|
| 普通职员 | 所有职员默认角色，使用个人中心、群聊、私聊 |
| 管理部门职员 | 被授予管理权限，对**普通职员**增删改查、看信息面板、禁言 |
| 总裁 | 系统唯一，拥有管理部门职员全部功能 + 管理部门任免（授予/撤销管理权限） |

### 权限矩阵

| 功能 | 普通 | 管理部门 | 总裁 |
|---|:---:|:---:|:---:|
| 登录 / 个人中心（信息/密码/头像） | ✓ | ✓ | ✓ |
| 部门群聊 / 全员群聊 / 私聊 | ✓ | ✓ | ✓ |
| 员工管理（增删改查） | — | ✓（仅普通职员） | ✓ |
| 信息面板（仪表盘/统计） | — | ✓ | ✓ |
| 禁言 | — | ✓（普通职员） | ✓（管理层及以下） |
| 授予/撤销管理权限 | — | — | ✓ |

> 操作范围：不能操作本人；管理部门职员仅能操作普通职员；总裁可操作管理层及以下；总裁本人不可被操作。

### 登录规则

1. 账号 = **姓名**（英文不区分大小写）或**员工编号**（如 `207`）。
2. 默认密码 `123456`，密码哈希存储，可在个人中心修改。
3. 账号（姓名）唯一；token 会话，未登录访问重定向登录页。

| G-06 | 持久化 | 消息存库，刷新不丢失 | 高 |

| G-08 | 成员联动 | 职员增/转部门/离职，群成员自动更新 | 中 |

## 四、后端接口（`/api/v1`）

| 分组 | 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|---|
| 认证 | POST | `/auth/login` | 登录（姓名或编号+密码），返回 token+用户 | 公开 |
| 认证 | POST | `/auth/logout` | 退出 | 登录 |
| 认证 | GET | `/auth/me` | 当前用户信息 | 登录 |
| 个人中心 | PUT | `/me` | 修改邮箱/电话 | 登录 |
| 个人中心 | PUT | `/me/password` | 修改密码 | 登录 |
| 个人中心 | POST | `/me/avatar` | 上传头像（multipart） | 登录 |
| 群聊 | GET | `/groups/my` | 我的群聊（部门群+全员群） | 登录 |
| 群聊 | GET/POST | `/groups/dept/messages` | 部门群历史/发送 | 登录（禁言不可发） |
| 群聊 | GET/POST | `/groups/all/messages` | 全员群历史/发送 | 登录（禁言不可发） |
| 私聊 | GET | `/contacts` | 可私聊职员列表 | 登录 |
| 私聊 | GET/POST | `/private/messages` | 私聊历史（`contact_id`）/发送 | 登录 |
| 私聊 | GET | `/private/conversations` | 会话列表（含未读，新消息置顶） | 登录 |
| 私聊 | POST | `/private/read` | 标记与某职员的私聊已读 | 登录 |
| 私聊 | GET | `/private/unread-total` | 未读私聊总数（侧边栏红点） | 登录 |
| 禁言 | GET | `/mutes` | 禁言列表 | 管理层 |
| 禁言 | POST | `/mutes` | 禁言 `{employee_id, reason, mute_minutes?}` | 管理层 |
| 禁言 | DELETE | `/mutes/{id}` | 解除禁言 | 管理层 |
| 总裁 | GET | `/managers` | 管理部门名单 | 总裁 |
| 总裁 | POST | `/managers` | 授予管理权限 | 总裁 |
| 总裁 | DELETE | `/managers/{id}` | 撤销管理权限 | 总裁 |
| 员工管理 | GET | `/employees/search` 等 | 组合查询/分页/增删改查 | 管理层 |
| 统计 | GET | `/overview`、`/departments`、`/jobs` | 仪表盘/字典 | 管理层 |

**约定**：除登录外均需 `Authorization: Bearer <token>`；错误统一 `{code, message}`（401 未登录/失效、403 无权限、404 不存在、422 参数错误、500 兜底）。

## 五、数据需求

**库**：MySQL `my-first-sql`（utf8mb4），连接见 `database.py`。

| 表 | 说明 | 关键字段 |
|---|---|---|
| `t_employees` | 员工（含登录） | `EMPLOYEE_ID`(varchar主键)、`FIRST/LAST_NAME`、`EMAIL`、`PHONE_NUMBER`、`HIRE_DATE`、`JOB_ID`、`SALARY`、`COMMISSION_PCT`、`MANAGER_ID`、`DEPARTMENT_ID`、`PASSWORD_HASH`、`ROLE`(STAFF/MANAGER/PRESIDENT)、`AVATAR` |
| `t_departments` / `t_jobs` | 部门 / 职位字典 | 原有字段 |
| `t_group_messages` | 群聊消息 | `MESSAGE_ID`(自增)、`GROUP_TYPE`(DEPT/ALL)、`GROUP_ID`(部门ID或0)、`SENDER_ID`、`CONTENT`、`CREATED_AT` |
| `t_private_messages` | 私聊消息 | `MESSAGE_ID`、`SENDER_ID`、`RECEIVER_ID`、`CONTENT`、`CREATED_AT` |
| `t_unread` | 私聊未读数 | `ID`、`EMPLOYEE_ID`(所属)、`CONTACT_ID`(对方)、`COUNT`；`(EMPLOYEE_ID, CONTACT_ID)` 唯一 |
| `t_mutes` | 禁言记录 | `MUTE_ID`、`EMPLOYEE_ID`、`OPERATOR_ID`、`REASON`、`MUTE_UNTIL`(空=永久)、`CREATED_AT` |

**初始数据**：总裁=员工207「鲤悠悠」（职位 AD_PRES，唯一）；管理部门职员=员工100/101/102（部门90高级管理层）；其余普通职员；默认密码全部 `123456`。无部门员工已删除（如原178 Kimberely Grant）。

## 八、验收标准

| 编号 | 验收项 | 方式 |
|---|---|---|
| A-01 | 姓名/编号登录成功（英文大小写混输均可）；未登录跳转登录页 | 登录页操作 |
| A-02 | 初始密码 `123456`，改密后旧密码失效 | 个人中心 |
| A-03 | 普通职员只见个人中心/群聊/私聊；管理层见管理菜单；总裁见总裁菜单 | 分别登录核对 |
| A-04 | 部门群仅同部门、全员群含全部职员，消息持久化 | 发消息后刷新 |
| A-05 | 私聊任意职员，消息持久化 | 发起私聊并刷新 |
| A-06 | 管理层对普通职员增删改查；普通职员调用管理接口 403 | 操作+越权请求 |
| A-07 | 禁言后群聊发言被拒、可查看可私聊；到期自动解除 | 禁言验证 |
| A-08 | 总裁授予/撤销权限后角色即时生效 | 总裁操作后换账号验证 |
| A-09 | 总裁不可被禁言/删除 | 总裁账号核对 |
| A-10 | 未登录/普通职员访问管理接口返回 401/403 | 构造请求验证 |
| A-11 | 上传头像后全站显示；无部门员工不存在 | 上传+核对数据 |

## 九、风险与说明

| 风险/说明 | 建议 |
|---|---|
| 姓名重复导致账号冲突 | 新增时校验姓名唯一，重复追加编号 |
| 权限只在前端隐藏菜单 | 后端每个接口独立鉴权 |
| 群聊无实时推送 | 5s 轮询，可升级 WebSocket |
| 旧表结构变更 | 先 `ALTER TABLE` 加列并初始化角色/密码（`migrate.py`） |
| `t_employees` 主键 varchar 类型 | 跨表映射统一 `int()` 归一化（见开发问题 P15） |
| 消息量增长 | 统一分页加载 |
